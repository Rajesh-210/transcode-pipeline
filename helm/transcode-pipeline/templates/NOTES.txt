# Transcoding Pipeline Helm Chart

## Overview

This chart deploys a production-ready media transcoding pipeline with:
- FastAPI service for video upload and status monitoring
- FFmpeg-backed worker for HLS transcoding
- Redis queue for event-driven job dispatch
- KEDA autoscaling for zero-downtime worker pool
- Ingress for external API access

## Prerequisites

- Kubernetes cluster 1.20+
- KEDA operator installed (if keda.enabled=true)
- Nginx Ingress Controller installed (if ingress.enabled=true)

## Get Started

```bash
helm install transcode-pipeline ./helm/transcode-pipeline \
  --namespace transcode-pipeline \
  --create-namespace
```

## Configuration

| Parameter | Description | Default |
|-----------|-------------|---------|
| `image.api.repository` | API container image repository | chilukurir/transcode-api |
| `image.api.tag` | API container image tag | latest |
| `image.worker.repository` | Worker container image repository | chilukurir/transcode-worker |
| `image.worker.tag` | Worker container image tag | latest |
| `replicaCount.api` | Number of API replicas | 2 |
| `replicaCount.worker` | Number of worker replicas | 1 |
| `keda.enabled` | Enable KEDA autoscaling | true |
| `keda.minReplicaCount` | Min worker replicas (KEDA) | 0 |
| `keda.maxReplicaCount` | Max worker replicas (KEDA) | 10 |
| `storage.backend` | Storage backend: local, s3 | local |
| `ingress.enabled` | Enable Ingress resource | false |

## Accessing the Application

After installation, access the API:

```bash
# Port-forward the API service
kubectl port-forward svc/transcode-api 8000:8000 -n transcode-pipeline

# Open API docs
open http://localhost:8000/docs
```

If Ingress is enabled, configure DNS to point to your Ingress LoadBalancer IP.

## Uninstall

```bash
helm uninstall transcode-pipeline -n transcode-pipeline
kubectl delete namespace transcode-pipeline
```
